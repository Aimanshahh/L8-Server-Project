## §B — Vehicle marker smoothing + smooth map follow (uncommitted)

### B.1 `public/assets/js/gps-smooth.js` — **NEW**
* **Used by:** every page that loads `assets/js/app.js` (objects map, sharing map, default layout).
  Loaded *before* `app.js` via `asset_resource('assets/js/gps-smooth.js')`, so it is cache-busted by
  mtime automatically. Exposes one global: `window.GpsSmooth`.
* **What it is:** the whole animation engine — a single `requestAnimationFrame` loop that glides every
  moving marker, plus Follow mode for the map viewport. No dependencies; works with plain `{lat,lng}`.
* **Why it exists:** the previous animation called Leaflet's `slideTo()` with a duration clamped to
  `Math.max(3000, min(elapsed, 60000))`. Every poll restarted that animation, every position in a
  burst restarted it again, and the map followed via polling `fitBounds()`, which snaps.
* **What it does:**
  * learns per device how often it reports (`intervalEma`) and how fast it really moves (`speedEma`);
  * glide duration = remaining distance ÷ observed speed, bounded by the learned cadence → a device
    that reports every 3 minutes glides slowly instead of fast-then-freeze;
  * retargets mid-glide from the *rendered* position → a new fix changes direction/speed only, never
    the position (no jump, no restart, no jitter);
  * collapses same-timestamp bursts to the newest fix, ignores duplicate coordinates and
    stale/out-of-order backlog fixes, and snaps once on physically impossible movement
    (>250 km/h implied), >5 min of silence, a hidden tab, or when the animation setting is off;
  * Follow mode pans the map fractionally per frame inside a dead zone (eased, sub-pixel accumulator),
    never `setView`, never `fitBounds`; pauses when the user drags the map;
  * optional road snapping via `GpsSmooth.enableOsrm(url)` (off by default, blended in, safe fallback).
* **Tuning:** `GpsSmooth.cfg` (documented in `MARKER_SMOOTHING_FIX.md` §4);
  `GpsSmooth.diagnostics()` / `GpsSmooth.stats()` for live inspection.

### B.2 `public/assets/js/app.js` — modified (the live bundle; this is what the browser loads)
* **Used by:** `Frontend/Layouts/{loged,default,sharing}.blade.php` (`<script src=.../assets/js/app.js>`).
* **Changes and reasons:**
  1. `Device.updateLayer()` — the animation branch no longer calls `layer.slideTo(...)` with a
     hard-coded duration. It now calls `window.GpsSmooth.move(layer, position, {animate, ts, speed})`
     when animation is enabled, and `window.GpsSmooth.place(layer, position)` when it is not
     (instant snap — this also covers markers that sit inside a cluster and are not drawn). The
     `setTimeout(..., 50)` wrapper and the `layer._gpsLastUpdate` bookkeeping are gone; the engine
     owns the clock. *Why:* one animation authority, no restarts, no hard-coded duration.
  2. `Device.onLayerRemove()` — now calls `window.GpsSmooth.forget(layer)`.
     *Why:* removes the marker's animation state when it leaves the map (cluster/refresh), so a
     removed marker cannot keep a hidden glide alive.
  3. Devices controller — added `startFollow()`, `stopFollow()`, `toggleFollow(value)`,
     `followControl(value)`, `isFollowing()`; `select()` calls `startFollow()` when a device is
     selected and `stopFollow()` when it is deselected; `init()` registers
     `GpsSmooth.onFollowChange(...)`; `list()` (sidebar refresh resets the selection) stops follow;
     `toggleFitBounds(true)` stops follow. *Why:* the visible Follow toggle, auto-follow on device
     selection, and correct hand-over between "fit objects" and follow mode. While following,
     `app.settings.fitBounds` is switched off — that polling recenter was what made the map snap
     instead of pan.
  4. The old inline `GPS-SMOOTH v1` block at the end of the bundle was **kept but neutered**: it now
     assigns `window.GpsSmoothLegacy` instead of `window.GpsSmooth`, with a banner comment saying it is
     superseded. *Why:* the bundle has no build step and deleting 160 lines by hand was riskier than
     making them inert; the alias guarantees v1 can never shadow v2.

### B.11 Bugs found and fixed during review (worth knowing)
1. **Follow pan direction was inverted.** Real Leaflet moves a fixed marker *left* when you call
   `panBy([+x, …])` (verified live against Leaflet 1.0.3). The engine was subtracting, so the map ran
   away from the vehicle. Fixed to `+dx·alpha` / `+dy·alpha`. My Node map stub had mirrored my wrong
   assumption, which is exactly why the browser harness was built — it caught it.
2. **Mid-glide retarget re-derived the marker position from the wall clock**, so a fix arriving after
   the loop had been idle for a while produced a 150 m jump. Now it retargets from the last *rendered*
   position; the Node test asserts the worst single-frame step stays under 8 m.
3. **Sub-pixel follow stall:** rounding each pan to whole pixels left the marker parked a few pixels
   outside the dead zone. Added a sub-pixel accumulator (remainder carried to the next frame).
4. **Coasting overshoot:** creeping *past* the last known fix made the marker rest away from the last
   reported position. `coast` is now **off** by default (opt-in, capped at 25 m / 5 % of the last
   segment) so a late fix leaves the marker exactly where the vehicle was last seen.
5. **`_reset()` left a stale rAF handle** (test-only observability fix, also makes "stop the loop"
   deterministic).
